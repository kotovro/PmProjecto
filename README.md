## Правила коммитов
Каждый из коммитов должен содержать один из следующих тегов:
- docs - если была обновлена документация(README, или иные материалы)
- feature - если был добавлен код, связанный с задачей
- refactor - если не добавлялась новая функциональность в коде, но изменялась уже существующая
- merge - если это коммит-слияние

В репозитории принято решение использовать явное слияние (merge) вместо rebase, чтобы сохранять историю разработки и не переписывать существующие коммиты. Это особенно важно для общих веток, с которыми одновременно работают несколько разработчиков. Merge-коммит явно фиксирует момент объединения изменений из разных веток.

Формат сообщения коммита:
<тег>: <Текст сообщения коммита>

Формат сообщения - описание действия, в третьем лице. Пример коммита : 
```vi 
docs: Adds README file with necessary information on team, project structure and commit rules
```
